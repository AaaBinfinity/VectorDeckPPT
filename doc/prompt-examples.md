# VectorDeckPPT 提示词示例

这些示例用于调用 `$vectordeckppt`。资料与沟通目标是核心输入；页数、视觉方向和输出位置等非关键参数缺失时，Skill 可以提出合理默认值，但必须把默认项写入完整需求合同并获得确认后才能开始。

Skill 会先用少量分组问题补齐受众、目标、场景、资料、事实边界、页数、语言、视觉、品牌和交付信息，再提交合同摘要供确认。如果描述存在事实错误、矛盾，或不同理解会改变叙事方向，会继续提问并等待回答。

## 最短调用

```text
使用 $vectordeckppt 根据这份 Markdown 制作一套 10 页中文项目汇报 PPT。
请先补齐并汇总完整需求合同，等我确认后再开始资料综合和逐页内容。
```

## 完整请求模板

```text
使用 $vectordeckppt 根据【资料、附件或本地路径】制作一套【页数】页的【语言】PPT。

主要受众身份/角色：
受众知识水平与决策权：
次要受众：
演示场景：
沟通目标或期望行动：
必须保留的事实或数据：
希望采用的视觉性格：
视觉来源：选择内置方向 / 上传参考模板或截图 / 由 Agent 推荐 3 套后选择 / 明确委托 Agent 代选
不要出现的视觉风格：
品牌与素材约束：
必须保留/禁止改写的事实：
可编辑性要求：
内容密度：默认内容丰富，核心页优先使用文字解释、图表、图解和证据标注
字体一致性：普通页标题使用整套唯一的精确字号、字体和字重；同页同级标题、标签使用相同 token
最终交付目录：默认使用当前目录下的 pptoutput/

请先检查信息是否完整，集中提问并提交需求合同摘要；等我明确确认合同后，再读取资料
并提交完整的文字版逐页内容供我确认；文字内容批准后，只生成最多 3 页有代表性的
SVG/PNG 视觉样稿供我确认；合同确认和两次内容/视觉批准后再生成全套页面、编译并验证 PPTX，同时保留
源 SVG、PNG 预览和 compilation-report.json。
```

没有指定视觉来源时，Skill 应先给出 3 个符合受众与场景的内置候选，说明各自的优势和取舍。用户可以回复“选第 2 套”、“我上传一个 PPTX/截图作为参考”，或“由 Agent 选择并写入需求合同”。

上传参考模板时可以这样写：

```text
使用 $vectordeckppt 制作演示文稿。我上传的 PPTX 和 3 张截图只作为视觉参考：
请提取艺术标题、图片裁切、留白、色彩和页面节奏，不复制其中的水印、Logo、
受保护角色或未授权图片。艺术字只用于封面、章节和少数关键结论；
普通页标题和正文保持统一且易读。请先总结你理解的视觉语法并写入需求合同，
等我确认后再开始资料综合。
```

“内容丰富”默认不是堆满文字，而是普通内容页同时具备明确结论、必要解释、具体证据或例子，以及影响或下一步。在资料允许时，约三分之二的核心内容页应使用真正承担说明作用的图表、图解、表格、流程、矩阵或标注图；没有真实数据时使用诚实的概念结构，不伪造数字和趋势。

字体规则中的“统一”指精确统一，不是相近即可。所有普通页面标题共享一个角色 token；同一页内承担相同层级的标题、标签或数字共享同一 token。若文字放不下，应优先改写、换行或调整布局，不要单独缩小字号。

## 项目介绍

```text
使用 $vectordeckppt 根据 PRD、README 和代码结构制作 10 页中文项目介绍。
主要受众是开发者和潜在用户，目标是让他们理解项目定位、端到端工作流、
核心能力、能力边界和使用方式。

视觉采用明亮科技系统：白底、深蓝正文、青色表示系统转换，内容丰富但层级清晰。
不要使用通用蓝紫渐变、重复三卡片模板或无意义图标。

普通页标题统一使用同一个精确字号、字体和字重；同页同级模块标题必须完全一致。
每个核心页至少讲清结论、解释、具体证据或例子和下一步，优先用流程、架构图、
对比表、能力矩阵或带标注的界面图承载信息，不要只放一句标题和几行占位文案。

先输出完整逐页文字版；我批准后制作封面、工作流页和最复杂能力页三张样稿；
视觉批准后再完成全套。最终交付到当前目录的 pptoutput/。
```

## 商业汇报

```text
使用 $vectordeckppt 将附件整理成 12 页季度经营汇报。受众是 CEO 和业务负责人，
核心任务是解释利润率下降的三个驱动因素并获得两项资源决策。

叙事采用“信号—原因—风险—建议—负责人”的路径。视觉采用数据优先的编辑风格：
暖白底、深色正文、少量朱红用于风险和关键偏差，使用大数字、直接标注和有节奏的
疏密变化；避免仪表盘、渐变和大量圆角卡片。所有结论必须能追溯到附件数据。
```

## 技术评审

```text
使用 $vectordeckppt 根据 PRD 和架构说明制作 15 页技术评审 PPT。受众是架构师和
研发负责人，重点讲清系统边界、关键数据流、故障隔离和迁移风险。

视觉方向像一份严谨的工程图册：严格网格、清晰拓扑、低饱和中性色，钴蓝只表示
主链路；禁止发光节点、赛博背景和装饰性电路线。架构页优先保证连接关系可读和
对象可编辑，复杂路径降级时必须在报告中说明。
```

## 路演与产品发布

```text
使用 $vectordeckppt 把产品资料重构为 10 页路演 Deck。受众是产业投资人，目标是
让他们相信需求真实、产品差异明确且商业路径可执行。

视觉采用“高端克制 + 人文纪实”：大尺度标题、真实场景照片、深海军蓝背景与一处
明亮酸橙色强调，保持强烈留白和电影式节奏；不要使用握手照片、火箭图标、虚假 3D
图表或统一三列布局。结尾明确融资用途和下一步。
```

## 动态英雄式视觉

```text
使用 $vectordeckppt 将活动资料制作成 10 页发布演示。视觉采用 Dynamic Hero Editorial：
使用能成为画面主体的英雄字体、编辑式不对称、受控斜切、叠压、裁切、弧线、超大数字
和少量网点节奏；不要把页面做成横平竖直的卡片集合，也不要复制任何已有角色、Logo、
服装或 IP 识别元素。

证据页必须比开场页更克制，普通页标题和同页同级标题保持统一。若你判断现场、受众或
内容不适合这种强度，请在需求合同中说明风险并给出更专业的替代方向，等我确认后再开始。
```

## 重新设计已有 PPT

```text
使用 $vectordeckppt 重新设计现有 PPT，保留事实、页序和品牌色，但重写冗长标题并
优化视觉叙事。

先识别每页真正的结论，再为全套定义统一的字体、网格、图片裁剪和图表强调规则。
减少边框、阴影、图标和卡片数量，让每页只有一个主要视觉焦点。交付前对 SVG 预览
和最终 PPTX 逐页比较，特别检查中文换行、图片裁剪和 PowerPoint 字体偏移。普通页
标题使用整套唯一字号，同页同级标题保持完全一致，并在编译前通过严格字体审计。
```

## 确认阶段的回复方式

文字版确认时，可以直接指出需要修改的页码：

```text
文字结构确认，但第 4 页的结论改为【……】，第 7 页不要使用尚未验证的市场数字。
修改后再次提交完整文字版。
```

视觉样稿确认时，尽量描述可观察的视觉行为：

```text
整体方向确认。标题层级保留；卡片边框再弱一些，青色只用于流程转换，
数据页增加直接标注，图片页减少装饰元素。按此规则完成全套。
```

文字批准和视觉批准相互独立。文字发生实质修改后，受影响的视觉样稿需要重新确认。
